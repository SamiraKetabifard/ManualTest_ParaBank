# Test Plan

## 1. Objective

The objective of this project is to manually test the ParaBank web application and identify functional, validation, business logic, UI, and error-handling issues.

## 2. Scope

The following areas were included in testing:

- User Authentication
- User Registration
- Account Management
- Fund Transfers
- Bill Payments
- Loan Requests
- Transaction Search
- Contact Information
- Logout
- Administration

## 3. Testing Approach

Testing started with Exploratory Testing.

During exploration, application features were identified and tested using:

- Positive test cases
- Negative test cases
- Empty input testing
- Invalid input testing
- Boundary value testing
- Business logic testing
- Input validation testing
- UI validation
- Error handling

## 4. Test Case Types

### Smoke Testing

Basic testing to verify that the main application functionality is working.

### Functional Testing

Testing whether each feature behaves according to its expected functionality.

### Negative Testing

Testing invalid inputs and invalid user actions.

### Input Validation Testing

Testing whether fields accept only appropriate input values.

### Boundary Value Testing

Testing values at or near valid boundaries, such as zero and minimum amounts.

### Business Logic Testing

Testing business rules such as account balances, transfers, loan processing, and financial transactions.

### UI Testing

Testing displayed messages, labels, confirmations, and user-facing information.

### Security Testing

Basic testing of authentication, authorization, and access control behavior.

## 5. Entry Criteria

- ParaBank application is accessible.
- Test environment is available.
- A valid test user can be created.

## 6. Exit Criteria

Testing is considered complete when the planned test cases have been executed and identified defects have been documented.

## 7. Deliverables

- Exploratory Testing Notes
- Test Cases
- Test Execution Results
- Bug Reports
- Screenshots / Evidence
- Test Summary
